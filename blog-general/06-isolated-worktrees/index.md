## 技巧名称与一句话概括

Git 工作树隔离：让每个并行任务在自己的目录和分支上修改、运行和验证。

## 核心原理与适用场景

同一仓库的工作树共享提交历史，但工作文件和暂存区分开。适合不依赖彼此未提交改动的修复、试验与对照审查。

## 低效写法与问题

> 两个会话在同一目录改代码，一个修分页，一个做搜索索引，最后再拆 diff。

两边可能交替覆盖同一个文件，测试结果也混在一起，很难知道哪些改动属于哪个任务。

## 正确应用与代码解释

在有提交的练习仓库里，先选未占用的分支名和同级目录：

```sh
git status --short
git worktree add -b experiment/search-index ../shelf-index-lab HEAD
git worktree list
```

`HEAD` 是试验基线，目录不包含原工作树未提交的修改。进新目录后先用 `git rev-parse --show-toplevel` 核验根路径，再启动 AI；交代只在这个目录比较新旧搜索结果，不自行合并。

## 关键点与常见陷阱

- 工作树不是容器：端口、数据库和权限可能共享。测试用隔离的本地数据，不带入真实凭据。
- 清理目录前先确认没有未保存的改动；命令报目录不干净时不要强制删除。

## 动手练习与小挑战

练习：在练习仓库的原目录和新目录各写一条不同的注释，分别运行 `git status --short`。挑战：把结果接回主分支前，用同一组重名标题证明旧索引与新索引的行为是否一致。
