每次发稿都要检查标题、栏目和草稿标记。如果需要一次次重打同样的提示词，就可以把它沉淀成一个只读 Skill。

{/* truncate */}

## 技巧名称与一句话概括

单职责 Skill：为反复出现的一类任务写清何时使用、读什么、产出什么。

## 核心原理与适用场景

项目约定适用于日常开发，Skill 则是按任务使用的流程。适合步骤稳定、输出可核对的工作，比如核对稿件元数据；不适合承接每次都不同、边界还没确定的需求。

## 低效写法与问题

```yaml
name: do-everything
description: 对项目做任何需要的优化
```

没有明确触发条件、范围和验收方式，既可能误用，也无法用同一个任务比较效果。

## 正确应用与代码解释

```md
---
name: article-preflight
description: 发布前只读检查指定 Markdown 稿件的标题、栏目和草稿标记
---

1. 输入是一个明确的稿件路径；未提供路径就先询问。
2. 只读取该文件，检查 title、tags 与 draft。
3. 输出通过项、阻塞项及对应字段；不修改或发布。
```

描述明确了调用时机，步骤将输入限制为一份文件，输出则能逐项检查。这是流程示例，不表示两种产品的安装路径、权限配置或触发行为相同。

## 关键点与常见陷阱

- 同时测一条应该用、一条不应该用的请求。
- 文字中的「只读」不是权限限制；实际工具权限应另外核对。

## 动手练习与小挑战

练习：把项目中一份发布前清单改成三个小步骤。挑战：加一条不适用的输入，确认不会把一篇普通翻译任务误判成发布检查。
