## 技巧名称与一句话概括

可验证切片：每个步骤都给出可观察结果、验证方式和不做的事。

## 核心原理与适用场景

按目录拆成「先写数据库、再写接口、最后写界面」，常常要等到最后才发现没理解需求。先贯通一条最窄路径，较早暴露数据流和交互问题，后续扩展也容易回退。

## 低效写法与问题

> 一次实现收藏、分组、排序和登录同步，全部做好再测。

出现问题时很难知道哪个需求或环节弄错。半成品也无法从读者入口验收。

## 正确应用与代码解释

```text
1. 页面内切换单篇收藏；点击后按钮文字变化，再点恢复。
2. 增加本地持久化；刷新后仍保留收藏，取消后刷新不恢复。
3. 再规划账号同步；先定义无网络与服务失败的表现。
本轮只做第 1 步，不新增接口或存储。
```

```js
function toggleFavorite(ids, id) {
  return ids.includes(id) ? ids.filter(x => x !== id) : [...ids, id];
}
```

这个函数只负责一次状态切换，不引入存储依赖；连续点两次可回到原状态。界面显示同一份状态，因此可以在加持久化之前验收第一步。

## 关键点与常见陷阱

- 小步不等于只改一个文件。一次切片可以跨少量文件，只要目标单一、结果可验。
- 如果第一步可能改变接口或数据格式，先列出受影响的调用方再决定。

## 动手练习与小挑战

练习：把「订单列表加筛选和导出」拆成三个能单独验收的步骤。挑战：挑一个步骤写出失败时如何恢复，避免测试依赖上一步的临时数据。
