# 技巧 06：用 Plan 模式把复杂需求变成可执行清单

> 一句话概括：让 AI 先只许看、不许改，把方案写成带文件和验证方式的清单，你点头之后再落地。

{/* truncate */}

本篇聚焦如何在 Plan 模式里确认方案。跨工具的方法和练习见[通用技巧](/blog/general-tips/03-verifiable-slices)。

## 一、技巧名称与一句话概括

**技巧名称**：先规划后执行（Plan-First Execution）。

**一句话概括**：Plan 模式通过只读操作分析代码库并生成计划，把「边做边想」变成「想清楚再做」。

它是[技巧 05 三种模式](/blog/workbuddy-tips/05-modes)里 Plan 那一档的深度用法。

## 二、核心原理与适用场景

官方文档对 Plan Mode 的描述很精确：它让 AI **通过只读操作分析代码库并生成计划**。

这句话有两个关键点：

1. **只读**：规划阶段不会修改任何文件，所以你可以放心让它探索；
2. **生成计划**：产出的是步骤清单，不是代码，也不是笼统建议。

适用场景：

- 多步骤实现：功能要改 3 个以上文件；
- 代码探索：动手前必须彻底搞清楚现有结构；
- 交互式开发：需要和你一起敲定方案方向。

CodeBuddy Code 的开启方式：

```bash
# 会话中按 Shift+Tab 两次，直到显示 ⏸ plan mode on
# 或直接以规划模式启动
codebuddy --permission-mode plan
```

## 三、错误或低效写法及问题说明

```text
把鉴权系统重构成 JWT。
```

如果这句话在 Craft 模式下发出去，AI 会直接开改。问题在于：

- 你不知道它会改哪些文件，事后难以逐项核对；
- 它对「兼容旧用户」「数据库迁移」「测试策略」的默认选择，很可能和你的约束冲突；
- 改到一半发现方向不对，前功尽弃。

另一种低效写法是进 Plan 模式后只问一句「给我个计划」，拿到一份泛泛的「第一步分析、第二步实现、第三步测试」——这种计划没有可执行信息。

## 四、正确应用方式：重构认证系统的完整规划

**第一步：给出带结构的规划请求**

```text
（Plan 模式）
目标：把 @src/auth 下的 Session 鉴权迁移为 JWT。

请输出计划，包含以下四部分：
1. 影响文件清单（按 前端 / API / 数据层 分组）
2. 分步实施顺序，每步一句话说明产出
3. 风险点：兼容性、数据迁移、测试覆盖
4. 每步的验证命令或检查方式

只做只读分析，不要写任何代码。
```

**第二步：针对计划追问**

拿到计划后，不要急着执行，挑最不确定的地方追问：

```text
第 3 步提到要改数据库 schema，能先说明具体加哪些字段、
旧数据怎么回填吗？另外向后兼容的过渡期打算怎么设计？
```

Plan 模式的价值就在这两轮追问里——**在写第一行代码之前把分歧暴露出来**。

**第三步：确认方案后转成可执行切片**

```text
方案确认。现在开始执行第 1 步：
新增 @src/auth/jwt.ts，实现签发与校验两个函数。
约束：
- 不改动现有 Session 逻辑
- 导出函数签名保持不变
- 运行 npx tsc --noEmit 验证
```

执行完这一步，你再决定第 2 步要不要调整计划。**计划不是一次性合同，而是每完成一片就重新校准的地图。**

## 五、关键点与常见陷阱

**关键点**

1. 规划请求里明确要求「影响文件 + 步骤 + 风险 + 验证方式」四部分，缺一不可。
2. 只读阶段尽量多问，代价几乎为零；执行阶段再改，代价成倍上升。
3. 复杂任务用深度思考配合：在提示词里加「think deeply about edge cases」，CodeBuddy Code 默认关闭思考模式，可用 `Tab` 或该提示词触发。
4. 计划确认后立刻切片执行第一片，别让计划躺在对话里过期。

**常见陷阱**

- **计划里没有文件清单**：说明 AI 还没真正读过代码，只是一份模板。要求它 `@` 出具体文件。
- **计划里没有验证方式**：这类计划执行完你无法判断成败。
- **追问时又切换回 Craft**：一旦开始追问执行细节，AI 可能直接动手。确认当前模式状态。
- **把 Plan 当审批流程走形式**：拿到计划秒回「执行」而没有细看，Plan 就白开了。

## 六、动手练习与小挑战

**练习**：选一个你打算做的多文件功能，用上面四部分结构让 AI 出一份计划。然后检查：如果计划里去掉某个步骤，会不会导致后面的步骤无法进行？会的话说明步骤依赖没写清。

**小挑战**：把 AI 给出的计划原样发给它，加一句「请指出这份计划里最可能出错的假设」。看看它能不能自己找出盲点——这是 Plan 模式最省钱的一次质检。
