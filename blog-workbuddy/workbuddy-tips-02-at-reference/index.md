# 技巧 02：用 @ 引用把正确的文件交给 AI

> 一句话概括：与其描述「我那个登录组件」，不如用 `@` 把文件直接塞进对话——精确输入比精确描述更省力。

{/* truncate */}

本篇聚焦 WorkBuddy / CodeBuddy 的文件引用操作。跨工具的方法和练习见[通用技巧](/blog/general-tips/02-focused-context)。

## 一、技巧名称与一句话概括

**技巧名称**：精准上下文引用（`@` 引用）。

**一句话概括**：用 `@` 明确指定 AI 该读哪个文件、哪个目录，把「找文件」这一步从 AI 的猜测变成你的确定。

这是[技巧 01 四要素](/blog/workbuddy-tips/01-task-brief)里「输入」要素最直接的落地方式。

## 二、核心原理与适用场景

WorkBuddy 和 CodeBuddy Code 都支持在输入框中用 `@` 引用上下文：

- **`@` 单个文件**：文件内容会被加入对话。小文件直接注入，大文件会保留引用并提示后续按需读取。
- **`@` 目录**：提供目录列表和文件信息，**不包含文件内容**，适合让 AI 先了解结构。
- **WorkBuddy 另外支持**：拖拽文件到输入框、`Ctrl/Cmd + V` 粘贴截图、创建任务时 `@` 引用文件/文档/规则。
- **CodeBuddy Code 额外行为**：`@file` 会自动把该文件目录及父目录中的 `CODEBUDDY.md` 一并带入上下文（详见[技巧 06](/blog/workbuddy-tips/10-codebuddy-md)）。

原理很简单：AI 的上下文窗口是有限资源。你直接给出文件，它就不需要用多轮工具调用去扫描目录、打开错误的文件、再回头纠正。**精准引用同时提升了准确率和速度，还省下 token。**

**适用场景**：代码定位、Bug 排查、针对某个组件的重构、让 AI 参考现有规范写新代码。

## 三、错误或低效写法及问题说明

```text
看看我项目里的登录代码有什么问题。
```

这句提示词的问题不在措辞，而在**没有输入**：

1. AI 得先扫描整个项目，找出它可能认为是「登录代码」的文件——名字可能叫 `Login.tsx`、`AuthPanel.vue`、`sign-in.ts`，猜错就要重来；
2. 扫描过程会把大量无关文件内容读进上下文，挤占后续真正有用的空间（见[通用 02 · 从入口收集上下文](/blog/general-tips/02-focused-context)）；
3. 如果你有两个登录页（后台登录和前台登录），AI 大概率选错那个。

另一种低效写法是把整个 `src/` 目录 `@` 进来。目录引用只给文件列表、不给内容，AI 看完列表还是得再逐个打开文件——等于绕了一圈。

## 四、正确应用方式：定位并修复一个登录 Bug

假设你发现「勾选记住我后，刷新页面仍然要重新登录」。正确的派活方式：

```text
请排查「记住我」失效的问题。

已引用文件：
- @src/pages/Login.tsx（勾选开关的组件）
- @src/api/auth.ts（登录响应处理）
- @src/utils/storage.ts（本地存储封装）

现象：勾选记住我后登录成功，刷新页面仍跳转登录页。
预期：7 天内刷新应自动恢复登录态。

要求：
1. 先定位根因，说明涉及哪一行代码
2. 只修复根因，不要顺手重构其他代码
3. 修复后运行 npm test -- auth 验证
4. 暂不修改任何文件，先告诉我你的判断
```

**这段代码/提示词解决了什么**：

- 三个 `@` 引用把排查范围锁死在三个文件，AI 不会去翻无关的页面组件；
- 「现象 + 预期」构成最小值复现描述（详见[通用 05 · 最小复现](/blog/general-tips/05-minimal-repro)）；
- 第 4 条要求先判断再动手，避免 AI 一边猜一边改。

如果 Bug 伴随着界面报错，**直接截图粘贴**：在输入框按 `Ctrl/Cmd + V`，把报错弹窗贴进去，再配一句「报错如图所示，请结合 `@src/pages/Login.tsx` 定位」。文字描述三层弹窗很容易漏细节，截图不会。

## 五、关键点与常见陷阱

**关键点**

1. **文件引用给内容，目录引用给地图**：要 AI 改代码就 `@` 文件，要 AI 了解结构就 `@` 目录。
2. 一条消息里可以引用多个文件，但控制在 3–5 个以内，优先引用与任务直接相关的。
3. 引用时配合一句话说明「这个文件在任务里扮演什么角色」，避免 AI 看不懂为什么给它。
4. WorkBuddy 创建任务时还可以 `@` 规则和文档，把项目规范一起带进来。

**常见陷阱**

- **引用了文件却不说看什么**：AI 会把文件从头读到尾，浪费上下文。加一句「只看其中 token 存储的部分」。
- **以为 `@` 目录等于把代码全给它**：目录引用只有文件名列表，不包含内容。
- **引用过期文件**：改完代码忘了更新引用，AI 还是按旧版本分析。重新引用一次即可。
- **截图里的文字没说清**：贴图时补一句「重点看红框部分」，否则 AI 要自己判断重点。

## 六、动手练习与小挑战

**练习**：找一个你熟悉的项目，用 `@` 引用其中 2 个相关文件，让 AI 回答「这两个文件之间的调用关系是什么？」。对比一下：如果不使用 `@`、只说文件名，AI 的回答质量有什么变化？

**小挑战**：制造一个故意的错误（比如把某个函数参数顺序写反），然后只给 AI 截图和 `@` 引用，看它能否在不扫描整个项目的情况下定位到具体行。
