# 技巧 08：检查点与会话恢复——放手试错的安全网

> 一句话概括：AI 每次编辑前都会自动留检查点，改错了可以只回退代码、只回退对话，或两者一起回退。

{/* truncate */}

## 一、技巧名称与一句话概括

**技巧名称**：检查点回退与会话恢复（Checkpoint & Resume）。

**一句话概括**：检查点让你敢让 AI 试高风险方案，会话恢复让你关掉终端第二天还能接着干，两者都不需要重新解释背景。

## 二、核心原理与适用场景

**检查点**的工作方式：

- CodeBuddy Code 会在**每条用户提示之前**自动捕获当前代码状态；
- 检查点跨会话持久保存，30 天后自动清理（可配置）；
- 回退入口：终端里执行 `/rewind` 或连按两次 `Esc`；Web UI 里把鼠标移到某条用户消息上，点「回退到这里」。

回退时有三种选择：

| 选项 | 效果 |
|------|------|
| 仅对话 | 回退到某条消息，保留代码改动（该消息回填输入框，方便改后重发） |
| 仅代码 | 还原文件，保留对话 |
| 代码和对话都回退 | 两者都恢复到那个时间点 |

**会话恢复**则解决另一件事：

```bash
codebuddy --continue                      # 继续最近一次会话
codebuddy --resume                        # 打开会话选择器
codebuddy --continue --print "Show our progress"
```

用 `/rename` 给会话起描述性名字（如 `oauth-migration`、`debugging-memory-leak`），以后好找。官方建议：**把会话当成分支**——不同工作流有各自独立的持久上下文。

**适用场景**：尝试不确定方案、功能迭代、跨天任务、长任务中断后续接。

## 三、错误或低效写法及问题说明

**错误一：以为检查点能撤销一切**

检查点**只跟踪 AI 文件编辑工具所做的更改**。通过 Bash 命令执行的文件操作不会被跟踪：

```bash
rm file.txt
mv old.txt new.txt
cp source.txt dest.txt
```

这些改动回退不了。手动在 IDE 里改的、其他并发会话改的，也通常不会被捕获。

**错误二：把检查点当 Git 用**

检查点是会话级的快速恢复，不是版本控制。它没有提交信息、没有分支、没有远端。正式项目该提交还是得提交。

**错误三：关掉终端就从头解释**

不知道有 `--continue`，第二天重新开会话，花十分钟把昨晚的背景再说一遍。

## 四、正确应用方式：一次有风险的重构

**第一步：先提交 Git，再大胆试**

```bash
git add . && git commit -m "chore: checkpoint before auth refactor"
```

**第二步：让 AI 试方案**

```text
尝试把 @src/auth/session.ts 改为 JWT 实现。
这是一个探索性尝试，如果遇到困难直接告诉我，我们来回退。
```

注意提示词里的「探索性尝试」——它告诉你 mental 上已经准备好回退，AI 也不必硬撑。

**第三步：不满意就精确回退**

执行 `/rewind`，选择「仅代码」回退到尝试前的文件状态，但**保留对话**——这样 AI 还记得刚才为什么失败，下一次尝试可以避开同一个坑。

这正是「仅代码」选项的价值：**代码归零，经验留存**。

**第四步：跨天续接**

第二天：

```bash
codebuddy --resume
# 从列表里选择 oauth-migration 会话
```

或者先 `/rename oauth-migration`，之后直接：

```bash
codebuddy --continue
```

恢复时会反序列化完整消息历史，保留工具调用记录与结果，使用原来的模型和配置。你只需说一句「继续第 3 步」。

**第五步：配合切片提交**

每完成一个可验证切片就 `git commit`（见[通用 03 · 可验证的任务切片](/blog/general-tips/03-verifiable-slices)）。检查点负责「刚才那步试错了」，Git 负责「上周那个版本是好的」。

## 五、关键点与常见陷阱

**关键点**

1. **重大操作前先 Git 提交**，检查点是补充不是替代。
2. 「仅代码回退 + 保留对话」是最常用的组合——保留失败经验。
3. 会话用 `/rename` 命名，把不同工作流当不同分支管理。
4. 执行 `/compact` 或自动压缩后，回退菜单只保留压缩后的提问，旧正文不再常驻内存。重要结论提前写进交接文档或 `CODEBUDDY.md`。
5. WorkBuddy 侧对应的是任务列表：已完成任务可重新进入继续补充消息，上下文会自动沿用。

**常见陷阱**

- **用 Bash 删了文件还想回退**：做不到。删文件前先确认。
- **检查点过期**：默认 30 天清理，长期分支靠 Git。
- **回退后发现对话里还留着旧结论**：选「代码和对话都回退」才能彻底清空。
- **多个会话同时编辑同一文件**：检查点只保证当前会话的跟踪，配合工作区隔离（见[通用 06 · Git 工作树隔离](/blog/general-tips/06-isolated-worktrees)）。

## 六、动手练习与小挑战

**练习**：在一个测试项目里，让 AI 做一个你明知会失败的改动，然后用 `/rewind` 分别试一次「仅代码」和「代码和对话都回退」，观察两种情况下 AI 后续回答的差异。

**小挑战**：把最近三个会话分别重命名为 `feature-xxx`、`debug-yyy`、`review-zzz`，第二天用 `--resume` 准确找回其中一个，验证是否无需重新解释背景。
