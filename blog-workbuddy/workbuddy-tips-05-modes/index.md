# 技巧 05：Ask / Plan / Craft——选对模式少走一半弯路

> 一句话概括：任务风险决定模式——探索用 Ask，复杂改动用 Plan，明确常规的活用 Craft。

{/* truncate */}

## 一、技巧名称与一句话概括

**技巧名称**：模式匹配（Mode Matching）。

**一句话概括**：在派活之前先判断「我要的是答案、计划还是结果」，再选对应模式，避免在错误的模式下反复拉扯。

WorkBuddy 提供三种工作模式；CodeBuddy Code 在终端里也有对应的权限模式。它们是同一件事在不同界面下的表达：**你想让 AI 拥有多大的行动权**。

## 二、核心原理与适用场景

| 模式 | AI 能做什么 | 适用任务 | 风险 |
|------|-----------|---------|------|
| **Ask**（问答） | 只回答、解读、分析，**不动文件** | 理解代码、方案探讨、技术选型 | 零 |
| **Plan**（规划） | 只读分析代码库，产出分步计划，**你确认后才执行** | 多文件改动、重构、架构调整 | 可控 |
| **Craft**（实干） | 收到指令直接执行 | 批量重命名、生成周报、明确的常规改动 | 最快，但要能回退 |

CodeBuddy Code 中，会话内按 `Shift+Tab`（Windows 也支持 `Alt+M`）循环切换权限模式；也可以用 `codebuddy --permission-mode plan` 直接以规划模式启动。设置文件里还能把 plan 设为默认：

```json
// .codebuddy/settings.json
{
  "permissions": { "defaultMode": "plan" }
}
```

**核心判断依据**：任务会不会改到你不熟悉、不好回退的地方？会 → 先 Ask 或 Plan；不会 → Craft。

## 三、错误或低效写法及问题说明

**错误一：在 Ask 模式下要求改代码**

```text
（Ask 模式）帮我把登录页的记住我功能实现了。
```

Ask 模式只会给你一段「你应该怎么改」的说明文字。你觉得 AI 没干活，其实是你选了「只许看不许动」的模式。

**错误二：在 Craft 模式下做高风险重构**

```text
（Craft 模式）把项目的鉴权系统从 Session 迁移到 JWT。
```

AI 会立刻改十几个文件。如果中途方向错了，你要一个个回退——虽然有检查点（见[技巧 12](/blog/workbuddy-tips/12-resume-rewind)），但理清哪一步走偏更费时间。

**错误三：全程只用一种模式**

有人因为怕出错，所有任务都用 Plan，结果简单的批量重命名也要确认两轮，效率反而下降。

## 四、正确应用方式：一次鉴权系统迁移

同一个目标，分三个阶段切换模式。

**第一步：Ask 模式——先搞懂现状**

```text
请分析 @src/auth 目录，说明当前 Session 鉴权的数据流：
1. 登录凭证存在哪、怎么校验
2. 哪些模块依赖它
3. 迁移到 JWT 可能影响哪些地方
只分析，不要修改任何文件。
```

拿到答案后，你心里有底了。

**第二步：Plan 模式——出方案不落地**

```text
基于刚才的分析，给出迁移到 JWT 的分步计划：
- 标注每一步涉及的文件
- 标注兼容性与数据迁移风险
- 给出每步的验证方式
先不要写代码，我来确认。
```

计划出来后继续追问两轮（这正是 Plan 模式的价值）：

```text
向后兼容怎么做？旧 Session 用户怎么办？
数据库需要加字段吗？迁移脚本放在哪？
```

**第三步：Craft 模式——执行确认后的第一片**

```text
按计划执行第 1 步：新增 JWT 签发与校验工具函数。
验收：npx tsc --noEmit 通过，不改动现有登录流程。
```

只执行一片，验证后再进行下一片（切片的做法见[通用 03 · 可验证的任务切片](/blog/general-tips/03-verifiable-slices)）。

## 五、关键点与常见陷阱

**关键点**

1. **同一任务可以中途换模式**：Ask 摸底 → Plan 规划 → Craft 执行，是最稳的节奏。
2. 不确定选哪个时，**先用 Ask 问一句「这个改动涉及哪些文件？」**，答案会告诉你风险等级。
3. WorkBuddy 里任务可「保存到工作空间」，后续在 CodeBuddy 打开继续开发，模式切换不丢上下文。
4. 执行式任务至少要有回退手段（Git 或检查点）再开 Craft。

**常见陷阱**

- **把 Plan 当成无限讨论**：Plan 是产出可执行清单，不是头脑风暴。要求「给出步骤 + 影响文件 + 验证方式」。
- **Ask 模式里追问执行细节**：Ask 不写文件，问「把这个函数改成 async」没有意义。
- **Craft 模式不做切片**：模式选对了但一次让它改十个文件，照样难回退。
- **忘了自己当前在哪个模式**：先看界面提示（终端显示 `⏸ plan mode on`），再发指令。

## 六、动手练习与小挑战

**练习**：给下面三个任务各选一个模式，并说明理由。

1. 想搞清楚 `@src/utils/request.ts` 里的拦截器执行顺序
2. 把 20 个测试文件从 `.js` 改成 `.ts`，并更新引用路径
3. 给订单表新增「退款状态」字段，涉及数据库、API、前端三处

**小挑战**：选一个你正在做的任务，刻意按 Ask → Plan → Craft 三段走一遍。记录每一段花了多久、返工了几次，对比你平时的「直接 Craft」方式。
